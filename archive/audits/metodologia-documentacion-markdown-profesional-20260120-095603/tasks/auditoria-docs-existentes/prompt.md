# Auditoria de Documentos Existentes

## Layer 1 Contexto Conversacional

Ahora que tenemos estandares claros GUIA_ESTILO_MARKDOWN.md es momento de aplicarlos a la documentacion existente

El usuario quiere saber Cuales documentos cumplen los estandares Cuales necesitan correccion Que cambios especificos hacer

Esta es la tarea de implementacion practica

---

## Layer 2 Tarea Tecnica

Objetivo Auditar TODOS los documentos md del framework vs GUIA_ESTILO_MARKDOWN.md y generar plan de correccion

Documentos a auditar

Criticos CLAUDE.md principal README.md raiz docs todos los md reports todos los md

Secundarios Archivos md en subdirectorios Documentos de proyectos archive

Metodologia de auditoria

1. Por cada documento Verificar cumplimiento de GUIA_ESTILO_MARKDOWN.md Checklist de 20 puntos Identificar violaciones especificas Calcular score de cumplimiento

2. Categorizar problemas Simbolos prohibidos detectados Densidad excesiva Inconsistencias Formato inadecuado Estructura incorrecta

3. Priorizar correcciones CRITICO simbolos decorativos ALTO inconsistencias evidentes MEDIO formato suboptimo BAJO mejoras cosmeticas

Output esperado

Crea auditoria_documentacion_framework.md con

1. Resumen Ejecutivo documentos auditados score promedio problemas criticos encontrados

2. Tabla de Cumplimiento por documento score 0 a 100 por cada checklist item problemas principales

3. Problemas por Categoria simbolos prohibidos lista de documentos inconsistencias detectadas formato inadecuado

4. Plan de Correccion Priorizado documento por documento cambios especificos a realizar esfuerzo estimado minutos

5. Documentos Ejemplares cuales ya cumplen 100 por que son buenos modelos a seguir

6. Recomendaciones Inmediatas top 5 cambios de mayor impacto documentos a corregir primero

Criterios de exito Lista completa de violaciones Plan accionable de correccion Priorizacion clara Score de cumplimiento por documento
